# 第2章 `XW`：对象不变，特征重组

## 2.1 从轴语义重新认识 `XW`

上一章建立了阅读矩阵表达式的八步流程，也初步判断了 `XW` 的求和方向。本章不再重复整套流程，而是集中研究这一种基本模式：参数矩阵 `W` 如何把每个对象的旧特征重组为新特征。

设：

```text
X: 对象 × 旧特征
X: n × d

W: 旧特征 × 新特征
W: d × k
```

其中：

```text
i：对象索引
j：旧特征索引
r：新特征索引

n：对象轴长度
d：旧特征轴长度
k：新特征轴长度
```

则：

```text
Y = XW
Y: 对象 × 新特征
Y: n × k
```

这里的三个长度各有明确来路。对象轴长度 `n` 从 `X` 进入输出；旧特征轴长度 `d` 对应相乘接口，在乘法内部被汇总；新特征轴长度 `k` 来自 `W` 的第二条轴，成为输出的第二条轴。矩阵动作可以概括为：

> 对每个对象，使用同一个参数矩阵，把旧特征重组为新特征。

这是一种特征变换。它保留对象轴，使 `X` 与 `Y` 的第 `i` 行继续对应同一个对象；它不要求旧特征轴和新特征轴一样长，也不要求二者具有相同含义。

以房屋数据为例，若 `X` 的行对应房屋，列对应面积、房龄、房间数等旧特征，而 `W` 的列定义若干新的表示维度，那么 `Y[i, :]` 仍描述第 `i` 套房屋，只是描述坐标已经改变。这里没有新增一批房屋，也没有把不同房屋合并成一行。

“对象不变”说的是对象身份和对象轴的对应关系得到保留，不是说对象的数值表示保持不变。恰恰相反，`XW` 的目的就是改变每个对象的特征表示。

## 2.2 元素展开：一个对象的新特征从哪里来

对：

```text
Y = XW
```

展开一个典型输出元素：

```text
Y[i, r] = sum over j of X[i, j] * W[j, r]
```

固定对象索引 `i` 和新特征索引 `r` 后，旧特征索引 `j` 遍历全部旧特征：

```text
Y[i, r]
= X[i, 1] * W[1, r]
+ X[i, 2] * W[2, r]
+ ...
+ X[i, d] * W[d, r]
```

这条元素式给出了 `XW` 的核心语义。

首先，新特征 `r` 来自旧特征的加权组合。`W[j, r]` 决定旧特征 `j` 如何参与新特征 `r`。若某个系数为零，相应旧特征不直接贡献；若多个系数非零，新特征就同时读取多个旧特征。

其次，求和索引是旧特征 `j`，不是对象 `i`。计算 `Y[i, r]` 时，式中读取的是 `X[i, 1]` 到 `X[i, d]`，对象索引始终固定。因此对象 `i` 的输出不会在这一步直接读取其他对象的输入。

从整行看，同一事实可以写成：

```text
Y[i, :] = X[i, :] W
```

整块矩阵则把相同形式的特征变换同时应用于全部对象：

```text
Y[1, :] = X[1, :] W
Y[2, :] = X[2, :] W
...
Y[n, :] = X[n, :] W
```

`XW` 因而同时包含两个层次：对单个对象而言，它把一行旧特征变成一行新特征；对整批对象而言，它复用同一个 `W`，批量执行这项操作。

这里要严格区分轴与索引。旧特征轴是矩阵的一条组织方向，长度为 `d`，其位置由索引 `j` 遍历；新特征轴长度为 `k`，其位置由索引 `r` 指定。元素式沿旧特征轴求和，不应表述为“对维度 `d` 求和”而忽略 `d` 只是轴长度。

## 2.3 参数矩阵 `W` 如何连接旧特征与新特征

`W` 不只是一块无标题的“权重”。它的两条轴分别是：

```text
W: 旧特征 × 新特征
W: d × k
```

因此：

```text
W[j, r]
```

连接旧特征 `j` 与新特征 `r`，表示前者在生成后者时使用的系数。`W` 的行轴和列轴提供了两种互补的阅读视角。

看第 `r` 列：

```text
W[:, r]
```

它收集了生成新特征 `r` 所需的全部系数。于是：

```text
Y[:, r] = X W[:, r]
```

表示为所有对象计算同一个新特征 `r`。一列回答的问题是：这个新特征从哪些旧特征取得信息，各自使用什么系数？

看第 `j` 行：

```text
W[j, :]
```

它描述旧特征 `j` 会怎样贡献给全部新特征。一行回答的问题是：这个旧特征的信息会流向哪些输出位置？

参数矩阵的数值可以由人工规则给定，也可以通过训练得到。数值怎样确定与给定参数后公式执行什么动作，是两个不同问题。本章只研究后者；即使暂时不知道训练方法，也可以依据 `W` 的行列轴准确解释每个参数连接了什么。

所有对象共享同一个 `W`，这是 `XW` 的重要结构假设。`W` 中没有对象轴，也没有 `W[i, j, r]` 这样的对象索引。因而，旧特征 `j` 到新特征 `r` 的连接系数不会因对象 `i` 不同而另换一套。共享参数使同一种特征变换可以一致地作用于任意一行。

这并不意味着所有对象得到相同输出。对象的输入行 `X[i, :]` 不同，经过同一个 `W` 后仍会产生不同结果。共享的是变换规则，不是对象的特征值。

`W` 也不必是方阵：

```text
k < d：新特征轴较短
k = d：新旧特征轴长度相同
k > d：新特征轴较长
```

这些关系只比较轴长度。`k = d` 不表示新旧特征含义相同，`k < d` 也不自动保证重要信息被保留。要解释输出，仍须知道 `W` 的列轴代表什么，以及结果将如何使用。

## 2.4 为什么对象之间不会在 `XW` 中混合

`XW` 保留对象轴，但更准确的边界是：它不对对象轴求和，因此不在这一步直接进行对象间的信息聚合。

元素式已经给出证据：

```text
Y[i, r] = sum over j of X[i, j] * W[j, r]
```

若改变另一个对象 `p` 的输入 `X[p, :]`，而保持对象 `i` 的输入和 `W` 不变，那么 `Y[i, r]` 不会直接变化，因为右侧没有读取 `X[p, :]`。只有 `Y[p, :]` 会受到相应影响。

从参数结构看，`W: 旧特征 × 新特征` 也没有同时容纳两个对象角色的位置。它能回答“旧特征怎样连接新特征”，却不能回答“对象 `i` 应以多大权重读取对象 `p`”。后一个问题需要带有目标对象轴和来源对象轴的关系结构，并沿来源对象轴进行信息聚合。

对象轴保留还可以通过行重排来理解。设 `P` 只负责重排对象行，则：

```text
(PX)W = P(XW)
```

先重排输入对象再做特征变换，与先做特征变换再按相同方式重排输出，结果一致。`XW` 不依据某个对象恰好处于第几行来选择参数，而是把同一个 `W` 应用于每一行。

不过，“对象不直接聚合”不等于“对象在完整模型中永远互不影响”。输入 `X` 可能已经包含此前聚合得到的信息，后续也可能再加入对象间的信息聚合。局部阅读时必须限定结论：单独的 `XW` 只重组当前每个对象已经拥有的特征，不负责从其他对象读取新信息。

因此可以划清两种基本动作：

```text
特征变换：沿旧特征轴求和，改变每个对象的描述方式
信息聚合：沿来源对象轴求和，改变目标对象的信息来源
```

本章只完整建立第一种动作。第二种动作将在第4章讨论。

## 2.5 从一维预测到多维输出

`XW` 可以出现在评分、预测、分类输出和中间表示中。与其按应用名称记忆，不如先识别输出类型：输出对象是谁，新特征轴有多长，每个位置代表什么。

### 一个输出：标量分数或预测值

若每个对象只需一个输出，可以使用列向量：

```text
w: d × 1
y_hat = Xw
y_hat: n × 1
```

用一维索引表示列向量元素时：

```text
y_hat[i] = sum over j of X[i, j] * w[j]
```

每个对象的 `d` 个旧特征被组合成一个标量。它可以被解释为预测价格、风险分数或质量得分，具体名称由任务决定。这里的 `1` 是输出轴长度；即使只有一个位置，也不能省略它的语义。

本章说明 `Xw` 表达什么，不讨论怎样选择使预测最优的 `w`。后者将在第5章以最佳近似为主线讨论。

### 多个输出：类别分数或多个预测目标

若输出轴有 `c` 个位置：

```text
W: d × c
S = XW
S: n × c
```

当该轴被定义为类别轴时，`S[i, r]` 是对象 `i` 对类别 `r` 的分数。`XW` 本身只生成分数；分数是否再转换为概率，属于后续操作，不能反过来塞进这次乘法的语义。

若同样长度的轴被定义为多个预测目标，`S[i, r]` 就表示对象 `i` 的第 `r` 个预测量。两种情形形状可以完全相同，输出类型却不同。决定类型的是轴语义和后续用途，不是符号 `c` 或某个具体长度。

### 中间输出：新的隐藏表示

若输出用于后续计算，可以写成：

```text
H = XW
X: n × d
W: d × h
H: n × h
```

`H[i, :]` 是对象 `i` 的新表示。隐藏特征通常不是输入中直接给出的字段，也未必有方便的自然语言名称，但它们仍构成一条具有明确长度和位置的特征轴。

三种输出可以统一为：

```text
X: 对象 × 旧特征
W: 旧特征 × 新特征
XW: 对象 × 新特征
```

其中新特征轴可以具有不同类型：

```text
长度为 1：一个标量输出
语义为类别：一组类别分数
语义为多个目标：一组预测量
语义为隐藏特征：供后续计算使用的新表示
```

所以，读到 `XW` 时，不能止于“输出是 `n × k`”。还要说明第一条轴仍逐个对应哪些对象，第二条轴属于哪一种输出类型，以及其中每个位置将怎样被解释。

## 2.6 偏置、非线性与连续特征变换

实际表达式常写成：

```text
H = sigma(XW + b)
```

设：

```text
X: n × d
W: d × h
b: 1 × h
H: n × h
```

先计算：

```text
Z = XW
Z: n × h
```

`Z` 有 `n` 行，而 `b` 只有一行。`Z + b` 采用广播：把同一个 `b[r]` 加到所有对象的新特征 `r` 上。元素式为：

```text
(Z + b)[i, r] = Z[i, r] + b[r]
```

若希望把广播显式写成普通矩阵运算，可以令：

```text
1_n: n × 1
b: 1 × h
```

于是：

```text
1_n b: n × h
Z + b    # 广播记法
Z + 1_n b    # 显式矩阵记法
```

两种写法表达同一件事：长度为 `h` 的偏置向量被复制到每个对象位置，而不是沿对象轴求和。完整元素式为：

```text
H[i, r]
= sigma(
    sum over j of X[i, j] * W[j, r]
    + b[r]
  )
```

若 `sigma` 逐元素作用，它只处理当前位置的数值，也不会直接引入对象间的信息聚合。对象轴仍然保留，特征表示则经过加权组合、偏移和非线性处理。

连续的纯线性特征变换只需保留一个必要结论：

```text
(XW_1)W_2 = X(W_1 W_2)
```

如果中间没有非线性或其他不能合并的操作，两次纯线性变换可以合成为一次。加入逐元素非线性后，一般不能再把整段表达式压缩为单个参数矩阵。完整的多层信息流将在第7章展开；这里仅需确认，各层都可以继续按对象轴和特征轴追踪。

## 2.7 `XW` 的边界、误读与语义诊断

上一章已经建立了形状、接口和求和方向的通用诊断。本节只补充 `XW` 特有的检查：共享参数假设、特征排列、输出类型和附加操作是否被正确表达。

**共享参数是否符合任务？**

单个 `W: d × k` 对所有对象使用相同系数。如果任务要求每个对象拥有一套不同的变换规则，或者系数需要根据对象自身动态生成，那么固定的共享 `W` 不能完整表达该要求。诊断时应追问：任务需要的是“同一规则作用于不同输入”，还是“不同对象使用不同规则”？

**旧特征的顺序是否与 `W` 的行一致？**

即使轴名称和长度都正确，位置顺序仍可能错位。例如 `X` 的列依次是“面积、房龄、房间数”，而 `W` 的行却按“房龄、房间数、面积”存放。此时乘法能够执行，参数却会连接到错误的旧特征。轴对齐不仅要求同一组特征，还要求位置对应一致。

**是否把输出轴长度当成输出类型？**

`k < d` 只表示新特征轴较短，不能仅凭这一点称为有效降维；`k = d` 也不表示只是复制原特征。类别分数、多个预测目标和隐藏表示可能具有相同形状。输出类型必须由轴定义和后续使用确认。

**偏置是否明确了复制方式？**

当 `b: 1 × k` 与 `XW: n × k` 相加时，应明确采用按对象广播，或写成 `1_n b`。如果 `b` 带有对象轴、类别轴或其他含义，就不能未经说明地套用同一种广播解释。

针对一个 `XW` 型表达式，可以在通用八步流程之后补问：

```text
1. W 是否确实应由所有对象共享？
2. W 的行顺序是否与 X 的旧特征顺序一致？
3. W 的列轴定义了哪一种输出类型？
4. 偏置与逐元素操作是否保持了预期的对象独立性？
```

这些问题不重复判断“能不能相乘”，而是检查一个形状与基本轴语义都成立的 `XW`，是否忠实表达了具体任务。

## 2.8 识别并设计逐对象特征变换

考虑一个非学生案例。某工厂记录 `n` 台设备的 `d` 项当前测量值，例如温度、振动、压力和功耗。现在希望为每台设备产生 `k` 个状态指标，供后续监测使用。任务要求所有设备采用同一套指标计算规则，并且这一阶段只使用每台设备自己的测量值。

先定义输入轴：

```text
对象：设备
旧特征：当前测量项

X: 设备 × 旧特征
X: n × d
```

再定义输出轴：

```text
输出对象：仍是原来的设备
新特征：k 个状态指标

Y: 设备 × 新特征
Y: n × k
```

任务要沿旧特征轴组合信息，并为每台设备保留独立的一行，因此参数矩阵应写成：

```text
W: 旧特征 × 新特征
W: d × k
```

最终表达式为：

```text
Y = XW
```

用元素式验收：

```text
Y[i, r] = sum over j of X[i, j] * W[j, r]
```

其中 `i` 索引设备，`j` 索引旧测量项，`r` 索引新状态指标。式子表明：设备 `i` 的状态指标 `r` 由该设备自身的各项测量值加权组合而成。所有设备使用同一个 `W`，但输入值不同，因此输出可以不同；式中没有来源设备索引，也没有沿设备轴求和，所以设备之间不直接进行信息聚合。

若还需加入每个状态指标共享的偏置并应用逐元素非线性，可以写成：

```text
H = sigma(XW + b)
```

其中 `b: 1 × k` 按设备广播；显式写法是：

```text
H = sigma(XW + 1_n b)
```

这个案例体现了设计逐对象特征变换时的三个决定：

```text
输入怎样按“对象 × 旧特征”组织
输出需要哪一种新特征轴
旧特征到新特征的共享规则怎样放入 W
```

只要任务要求每个对象独立使用同一规则改变特征表示，`XW` 就是应优先考虑的基本结构。验收时再检查元素式是否沿旧特征 `j` 求和、对象 `i` 是否保留、输出索引 `r` 是否具有任务要求的类型。

至此，`XW` 的核心语义已经完整建立：`W` 的行轴对齐旧特征，列轴定义新特征；每个参数连接一个旧特征位置和一个新特征位置；所有对象共享同一个 `W`；乘法沿旧特征轴求和，保留对象轴，却不直接聚合不同对象的信息。

若下一步需要让一个对象依据其他对象的信息改变表示，单独的特征变换就不够了。在进行信息聚合之前，还要先有一种方式表达“谁与谁有关”。下一章将从对象的特征表示出发，研究怎样构造关系矩阵。
