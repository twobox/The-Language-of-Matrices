# 第8章 从阅读公式到设计公式

## 8.1 把公式阅读流程反转为设计流程

前七章从已有公式出发，为矩阵标轴、展开元素、寻找求和维度，再恢复信息流：

```text
公式 -> 语义
```

设计公式时，方向反过来。问题先给出对象、资源与目标，我们要决定输出描述谁、允许读取什么、必须汇总哪条轴，再写出矩阵：

```text
语义 -> 公式
```

例如，任务要求“每名学生根据自己的学习特征得到预测，并在权限允许时参考其他学生”。不能先凭记忆写 `XW` 或 `AXW`，而应先问：

```text
输出为谁产生？
预测时哪些数据真实可用？
学生之间是否允许交互？
若允许，谁可以读取谁？
输出质量用什么标准衡量？
```

阅读时，元素展开用于解释已有表达式；设计时，它是验收测试。设计流程因此不是“选一个熟悉模型”，而是：

```text
任务与输出规格
-> 信息权限与数据条件
-> 对象、特征、关系及轴
-> 最小矩阵动作
-> 多步信息流
-> 元素与部署验收
-> 错误修正及方案比较
-> 最终表达式
```

本章不重讲前七章。`XW`、`QK^T`、`AX`、最小二乘和低维结构现在只是候选工具，是否使用必须由任务约束推出。

## 8.2 定义任务：对象、输入、输出与建模目标

设计起点不是输入矩阵，而是任务规格。至少写清：

```text
对象：输出逐个对应谁？
输入：部署时实际能够获得什么？
输出：每个对象要产生多少个量？
交互：是否允许对象读取其他对象？
目标：怎样评价预测、匹配或重建的好坏？
```

以学生成绩预测为例：根据 `n` 名学生的 `d` 项平时学习指标，预测每名学生的期末成绩。可写：

```text
X: 学生 × 学习指标
X: n × d

y: 学生 × 1
y_hat: 学生 × 1
```

若采用平方误差，任务目标还包括：

```text
minimize ||y - y_hat||^2
```

输出中的学生轴必须保留，学习指标要被汇总为一个预测值。若部署时只能看到每名学生自己的平时指标，设计就不能因为训练数据中有其他字段而越过权限。

同一份 `X` 也可能支持不同任务：

```text
预测每名学生一个值：学生 × 1
构造学生关系：学生 × 学生
构造指标关系：学习指标 × 学习指标
```

输入形状没有唯一决定公式。输出规格决定哪些轴要保留，任务允许的信息决定哪些依赖可以存在，评价标准决定“更好”究竟指预测误差、匹配质量还是重建误差。

设计前可先填一张最小规格表：

```text
输出对象与输出轴：
部署时可用输入：
允许的信息路径：
必须汇总的实体或特征：
目标函数或硬约束：
```

这张表会在公式出现前暴露最重要的建模假设。

## 8.3 先定轴语义，再定矩阵与形状

假设要产生用户—商品匹配分数。已知：

```text
X_user: 用户 × 用户属性
X_item: 商品 × 商品属性
```

目标输出是：

```text
R: 用户 × 商品
```

直接写：

```text
R = X_user X_item^T
```

只有在两侧列轴确实是同一匹配空间时才有语义。年龄、地区、消费频率与价格、品类、库存即使列数相等，也不能因数字相同而逐项匹配。

若两侧属性不同，可以先设计共享匹配空间：

```text
W_user: 用户属性 × 匹配特征
W_item: 商品属性 × 匹配特征

Q = X_user W_user
K = X_item W_item

Q: 用户 × 匹配特征
K: 商品 × 匹配特征
R = QK^T
R: 用户 × 商品
```

元素为：

```text
R[i, p]
= sum over j of Q[i, j] * K[p, j]
```

共同索引 `j` 必须表示同一组匹配坐标。仅给两条轴取相同名字还不够；两侧映射需要由共同任务联合学习，或由规则预先对齐。

同类实体也要区分角色：

```text
A: 目标学生 × 来源学生
```

两条轴长度都可为 `n`，但在 `AX` 中，来源学生轴被求和，目标学生轴进入输出。可靠的设计顺序是：

```text
先写轴代表的实体或特征
-> 再写轴长度
-> 最后决定乘法方向
```

若共同轴的含义无法说明，转置只能让数字对齐，不能修复语义接口。

## 8.4 选择基本动作并搭建最小信息流

动作选择应由任务约束触发，而不是按知识点逐项调用。下表把每种判断压缩为“约束—动作—最小结构—误用风险”。

| 任务约束 | 需要的动作 | 最小结构 | 主要误用风险 |
| --- | --- | --- | --- |
| 每个对象只能使用自己的旧特征产生新特征 | 逐对象特征变换 | `Y = XW` | 误以为层数增加会自动引入对象交互 |
| 要输出同一批对象的内积关系 | 对象关系构造 | `R = XX^T` | 与 `X^T X` 的特征关系混淆 |
| 两个集合要在共享空间匹配 | 跨集合关系构造 | `R = QK^T` | 两侧匹配特征只同维，不同义 |
| 每个目标要从允许的来源读取信息 | 来源对象聚合 | `H = AX` | 行列方向或归一化轴写反 |
| 要用有限线性表达近似目标 | 预测式加误差标准 | `y_hat = Xw`，并规定损失 | 把任意平方误差训练都称为正交投影 |
| 要以秩不超过 `k` 重建矩阵 | 低秩重建 | `X_k = U_k Sigma_k V_k^T` | 与一般窄隐藏层或特征选择混为一谈 |

若任务同时要求“读取来源并生成新特征”，最小组合可以是：

```text
H = AXW
```

其中 `A` 决定读取谁，`W` 决定怎样重组特征。若只需每个对象独立输出，就不应凭习惯加入关系矩阵；若只需关系分数，就不必自动接聚合；若任务没有重建目标，也不能只因隐藏维度较窄就宣称做了 PCA 或截断 SVD。

最小结构不是永远最优，而是设计基线。只有当任务约束或验收失败说明它不够时，才增加动态关系、非线性、独立分支或低维约束，并明确新增结构解决了什么问题。

## 8.5 组合变换、匹配、聚合与输出

考虑城市短时资源需求预测。每座城市有当前天气、库存、人口流动等特征；目标城市可以参考一组业务上允许的城市。固定地理邻近度并不足够，因为当前最有参考价值的来源会随天气系统、库存状态和流动模式改变。正是这种“来源相关性随当前输入改变”的任务判断，支持使用动态关系，而不是仅仅给注意力公式换一个场景名称。

定义：

```text
X: 城市 × 当前特征
Q = XW_Q
K = XW_K
V = XW_V
```

其中 `Q`、`K` 进入共享匹配空间，`V` 提供可读取内容。动态分数和权重为：

```text
R = QK^T
A = softmax(R + G, along source-city axis)
```

`G` 是资格掩码：允许来源取0，禁止来源视为负无穷。本例假设每个目标城市至少有一个部署时可见的合法来源；否则必须在设计中另行规定零聚合、默认来源或独立自身分支，不能对全禁止行直接使用 softmax。随后：

```text
H = AV
y_hat = Hw
```

这段设计成立需要三项任务依据：

```text
来源城市在部署时确实可见；
允许集合由业务规则给出；
来源重要性应随当前状态变化。
```

若第三项不成立，固定关系权重可能更简单、更稳定；若城市之间不允许共享数据，应退回逐城市分支。动态关系不是默认升级，而是针对“当前匹配会变化”的结构选择。

非线性位置也属于设计判断。例如：

```text
H_1 = A sigma(XW)
H_2 = sigma(AXW)
```

前者先形成每个来源城市的非线性内容，再聚合；后者先聚合和线性变换，再处理结果。形状可以相同，元素依赖却不同，不能借结合律互换。

## 8.6 用元素展开验收设计语义

设计验收的核心是把一个输出元素完全展开，并同时检查部署时的数据可用性。仍以上述预测为例：

```text
H[i, r]
= sum over p of A[i, p] * V[p, r]

y_hat[i]
= sum over r of H[i, r] * w[r]
```

合并后：

```text
y_hat[i]
= sum over p, r of
  A[i, p] * V[p, r] * w[r]
```

这说明目标城市 `i` 的预测直接读取来源城市 `p` 的 value 特征，并按 `A[i, p]` 加权。由于 `A` 又由匹配分数的一整行归一化得到，预测还依赖目标城市、候选来源及候选集合。设计者必须逐项回答：这些依赖在任务发生时是否允许、是否可获得、时间上是否早于预测目标？

每个公式至少通过以下验收：

```text
输出归属：这个元素在为谁计算？
直接来源：展开后读取了哪些输入行和输入列？
求和轴：哪些对象或特征被汇总？
权重连接：每个系数连接哪一个目标与哪一个来源？
间接依赖：归一化或动态权重还依赖哪些候选？
部署可用性：这些数据在预测时是否存在、可见且时间合法？
空集合边界：没有合法来源时输出如何定义？
```

数据可用性不是附加检查。若学生期末成绩本身被放入预测输入，`Xw` 的轴、形状和元素展开都可正确，但部署时目标尚不可见，设计仍然失败。训练时能访问的数据，不等于推理时有权使用的数据；离线构造的关系，也不等于上线时能够同步得到的关系。

低维匹配同样要验收：

```text
R_hat[i, p]
= sum over t of P[i, t] * Q[p, t]
```

它说明用户 `i` 与商品 `p` 只通过潜在因素 `t` 发生匹配。若任务要求新用户依赖已知属性，而设计只有自由参数 `P`，那么新用户在部署时没有可生成的行表示。这不是乘法错误，而是数据路径没有闭合。

元素展开因此是设计测试，不是公式完成后的装饰。无法说明一个输出在部署时从哪里得到，就还没有完成设计。

## 8.7 诊断并修正“维度正确但语义错误”

发现错误时，不要先加转置。按以下顺序诊断：

```text
输出轴
-> 共同轴
-> 元素展开
-> 信息方向
-> 归一化与边界
-> 部署数据可用性
-> 修改公式
```

常见错误及修正如下。

**接口实体错位。** `X: 学生 × 课程` 与 `W: 城市 × 需求类型` 即使课程数等于城市数，也没有共同语义。应重新定义连接课程与目标输出的参数，而不是转置凑形状。

**求和轴错误。** 任务要求学生读取其他学生，却只写 `XW`；元素展开只汇总特征。若已有 `A: 目标学生 × 来源学生`，应使用 `AX`，需要新特征时再接 `W`。

**关系方向错误。** 若原矩阵的行表示发送者、列表示接收者，直接用于 `AX` 会把行误读为目标。应先把原始通信约定转换为“目标 × 来源”，并记录这一转换。

**归一化方向错误。** `A: 查询 × 来源` 用于 `AV` 时，每个查询要在来源之间分配读取权重，因此沿来源轴归一化。沿查询轴归一化代表另一种资源分配语义。

**输出对象错误。** 任务要学生关系却写 `X^T X`，得到的是课程关系；应选择保留两条学生轴的结构。

**权限或时间错误。** 公式读取了未来信息、目标字段、未授权对象或部署时不存在的统计量。此时轴可完全正确，仍必须删去依赖、改用可用代理变量，或重定义任务。

**空来源未定义。** 一整行没有合法来源时，不能直接对全禁止分数做 softmax。需要独立自身分支、约定零邻居聚合或提供明确回退来源。

语义错误与建模选择不同。两个方案都通过上述检查时，才进入表达能力、成本和经验效果的比较。

## 8.8 比较多种合法方案及其建模假设

以用户—商品评分为例，以下方案都可输出“用户 × 商品”，但信息来源不同。

```text
方案一：自由潜在因素
R_hat = P Q^T
```

它假设用户和商品可由共同的 `k` 维潜在因素匹配。已见用户和商品可直接学习行表示，但新对象没有天然属性入口。

```text
方案二：已知属性映射
U = X_user W_user
V = X_item W_item
R_hat = UV^T
```

它假设已知属性足以产生匹配表示，可为有属性的新对象计算表示，但受属性质量与映射结构限制。

```text
方案三：两条信息路径相加
R_hat = P Q^T + UV^T
```

它同时使用交互历史形成的自由因素和已知属性，增加参数、计算与分支分工的不确定性。若自由因素已足够宽，属性分支未必扩大理论可表达集合，但会改变归纳偏置和冷启动路径。

实际评分损失通常只在已观测位置计算，不能把未观测评分自动当作真实零。方案比较要至少说明：

```text
部署信息来源；
可覆盖的新旧对象；
参数与计算成本；
结构约束和可解释性；
训练目标及观测机制。
```

还要准确区分三类常被“低维”一词混在一起的设计：

1. **瓶颈低秩参数。** 若 `B = W_h W_o` 且中间宽度为 `h`，则 `rank(B) <= h`。这是对参数矩阵的因子化约束；`d*h + h*c` 是否小于 `d*c` 仍要按维度计算。
2. **最小二乘列空间。** 对固定设计矩阵 `X`，任意 `Xw` 都在 `Col(X)` 中；平方误差最小二乘在这个可表达集合里找最接近 `y` 的预测。它描述预测向量的可达空间，不等于对 `X` 做低秩重建。
3. **PCA / SVD 重建。** 对中心化数据做 PCA，可用主方向投影并重建；截断 SVD 在 Frobenius 误差下给出矩阵的最佳秩 `k` 重建。它们优化数据重建或方差保留，不自动等同于为下游预测学习的窄隐藏层。

所以，两个方案形状相同、都含较窄维度，仍可能优化不同目标。语义验收判断“做了什么”，实验和领域判断再回答“是否有效”。

## 8.9 从单步表达式到完整信息流的分层设计

训练应逐层撤去脚手架，但每层都要有可提交、可验收的结果。下面只保留五层，每层使用“输入—提交—验收”的短格式。

### 第一层：选对单步动作

```text
输入：X: 节点 × 特征；A: 目标节点 × 来源节点。
提交：得到每个目标节点来源汇总的一个公式和一个元素展开。
验收：输出轴为目标节点；来源节点轴被求和；不误写成 XW。
```

### 第二层：自行设计参数轴

```text
输入：X: 对象 × d个旧特征；要求对象互不交互，输出 k个新特征。
提交：参数矩阵的轴、形状及完整表达式。
验收：共同轴为旧特征；对象轴始终保留；输出为对象 × k个新特征。
```

### 第三层：补全关系与读取

```text
输入：查询和候选来自不同属性空间；查询要动态读取候选内容。
提交：共享匹配表示、关系分数、归一化轴、value聚合及各中间轴。
验收：两侧匹配特征同义；权重沿来源归一化；聚合读取的是 value；空候选有边界规则。
```

### 第四层：加入目标、约束与部署检查

```text
输入：一个预测任务及训练数据说明。
提交：输出、损失、元素依赖清单和部署可用字段清单。
验收：输出与目标同轴；损失符合任务；没有未来信息、目标泄漏或未授权来源。
```

### 第五层：独立比较完整方案

```text
输入：只提供现实问题、权限和资源限制。
提交：任务规格、至少一个最小方案、一个有理由的替代方案及元素验收。
验收：每项结构都由任务约束推出；明确表达集合或低维假设；区分瓶颈参数、最小二乘列空间与 PCA/SVD 重建；能够说明何时退回更简单方案。
```

这五层不是五套大规模练习，而是一套逐步减少提示的提交规范。能力进阶顺序是：先选择动作，再设计接口；先闭合局部信息流，再承担目标、权限、边界和方案比较。

## 8.10 从问题描述完成可解释公式设计

最后从任务约束反向完成一个设备预测方案。

平台有 `n` 个设备，每个设备记录 `d` 项当前状态，要预测下一时刻的 `c` 项状态。设备 `i` 在预测时可以使用：

```text
自己的当前状态 X[i, :]
指向自己的上游设备 p 的当前状态 X[p, :]
```

它不能使用下游设备、无通信关系设备、未来状态或真实预测目标。自身信息权限由任务明确授予，不需要伪装成通信自环。

### 第一步：定义输入、输出和原始通信

```text
X: 设备 × 当前特征
X: n × d

Y: 设备 × 下一时刻目标
Y: n × c
```

令原始通信矩阵为：

```text
M: 目标设备 × 来源设备
M[i, p] = 1：设备 p 是设备 i 的合法上游
M[i, p] = 0：设备 i 不得从设备 p 读取
M[i, i] = 0：本方案不把自身信息补成通信自环
```

如果原始日志记录的是“发送设备 × 接收设备”，先转置并按设备顺序对齐，得到上述“目标 × 来源”约定。

### 第二步：把通信 `M` 变为聚合权重 `A`

若所有合法上游等权，可按每个目标的来源轴归一化：

```text
deg_in[i] = sum over p of M[i, p]

if deg_in[i] > 0:
    A[i, p] = M[i, p] / deg_in[i]
else:
    A[i, p] = 0 for every p
```

于是：

```text
A: 目标设备 × 上游来源设备
sum over p of A[i, p] = 1，若设备 i 至少有一个上游
```

这一步明确了 `M` 与 `A` 的区别：`M` 给出通信许可，`A` 给出当前模型采用的读取权重。若通信边有可靠强度，可先用强度替代二值1，再在合法来源内归一化；若权重要随当前状态动态变化，则还需另行设计打分，但必须始终用 `M` 屏蔽非法来源。

没有上游的设备，其 `A` 整行为0，邻居聚合定义为零向量。自身信息由独立分支保留，因此不需要擅自设置 `A[i, i] > 0`。

### 第三步：分别设计自身与上游分支

定义：

```text
W_self: 当前特征 × 隐藏特征
W_self: d × h

W_neighbor: 当前特征 × 隐藏特征
W_neighbor: d × h

b: 1 × h
```

两条信息路径为：

```text
H_self = XW_self
H_neighbor = AXW_neighbor
H = phi(H_self + H_neighbor + b)
```

`H_self[i, :]` 只读取设备 `i` 自己的当前状态；`H_neighbor[i, :]` 只读取 `M[i, p] = 1` 的上游状态。二者使用不同参数，允许模型区分“自己的读数”与“上游传来的读数”。偏置 `b` 沿设备轴广播，为每个设备使用同一组隐藏特征偏置。

没有上游时：

```text
H_neighbor[i, :] = 0
```

但自身分支仍然存在。这比临时补自环更忠实于权限定义，也避免把“自身读取”误称为“上游通信”。

### 第四步：产生输出并规定训练目标

定义：

```text
W_o: 隐藏特征 × 输出状态
W_o: h × c

Y_hat = H W_o
Y_hat: 设备 × 下一时刻状态
```

可采用训练目标：

```text
minimize ||Y - Y_hat||_F^2
```

平方误差规定了训练比较标准，并不自动说明模型具有普通线性最小二乘的闭式投影解释；是否成立还取决于 `phi` 与参数约束。

### 第五步：元素级与权限验收

令非线性前的中间量为 `T`。下式中 `i` 表示目标设备，`p` 表示上游来源设备，`j` 表示当前输入特征，`r` 表示隐藏特征，`q` 表示输出状态：

```text
T = XW_self + AXW_neighbor + b
```

展开：

```text
T[i, r]
= sum over j of X[i, j] * W_self[j, r]
  + sum over p, j of
      A[i, p] * X[p, j] * W_neighbor[j, r]
  + b[r]

Y_hat[i, q]
= sum over r of phi(T[i, r]) * W_o[r, q]
```

第一项只读取设备 `i` 自身，第二项只在合法上游 `p` 上求和。目标设备 `i` 和输出状态 `q` 保留；来源设备 `p`、输入特征 `j` 与隐藏特征 `r` 在相应阶段被汇总。

部署验收还要确认：

```text
X[p, :] 是预测时可获得的当前而非未来状态；
M 的方向已转换为目标 × 来源；
A 的非零位置没有越过 M 的通信许可；
无上游行按零邻居分支处理；
Y 只用于训练目标，不进入预测输入。
```

### 第六步：准确说明瓶颈与替代结构

若去掉 `phi`，可写：

```text
Y_hat
= X(W_self W_o)
  + AX(W_neighbor W_o)
```

令：

```text
B_self = W_self W_o
B_neighbor = W_neighbor W_o
```

则：

```text
rank(B_self) <= h
rank(B_neighbor) <= h
```

这是两条特征到输出路径的低秩参数化约束。它不保证参数一定更少：仅计算三个权重矩阵时，参数量为 `2*d*h + h*c`；若把偏置也计入，则为 `2*d*h + h*c + h`，需要与具体替代方案比较。它也不表示 `H` 是 PCA 主成分或 `X` 的最佳秩 `h` 重建。

若 `A` 固定，并改用不带瓶颈的线性设计：

```text
Z = concat(X, AX, along feature axis)
Y_hat = ZB
```

那么在平方误差下，普通多输出最小二乘使每个预测输出列位于 `Col(Z)` 中，并在该列空间内逼近对应目标。加入上述因子化与共享隐藏层后，系数集合进一步受限，不能再把结果简单称为对 `Col(Z)` 的任意最小二乘投影。

若任务真正要求“用 `h` 维结构重建当前状态”，应另设中心化、PCA投影或截断 SVD 重建目标；那是在优化输入矩阵的重建误差或方差保留。当前设备模型的瓶颈服务于下一时刻预测，目标不同，不能互相命名。

至此，最终公式由任务反向推出：

```text
M -> A
H_self = XW_self
H_neighbor = AXW_neighbor
H = phi(H_self + H_neighbor + b)
Y_hat = HW_o
```

它同时闭合了输出规格、通信权限、空上游边界、特征瓶颈、训练目标和元素级信息路径。公式不是设计起点，而是这些判断的压缩结果。

全书的两条能力路径最终在这里相遇：

```text
阅读公式：从符号恢复语义
设计公式：从语义构造符号
```

读公式时，元素展开揭示隐藏依赖；写公式时，它检验依赖是否忠实于任务。能够在两种方向之间往返，才算掌握矩阵的语言。
